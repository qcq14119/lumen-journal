# Lumen Journal · 拾光手账

AstrBot 4.29.1+ 的通用角色相册插件，首版面向 QQ / aiocqhttp 与 SnowLuma。

这是 **0.1.0 预览版**，支持角色参考生图、管理 UI、本地持久化、QQ 发图与空间发布。生成后续接发布、九图发布及站点异步任务的实际兼容性仍需在目标环境验证。

## 使用

1. 登录有权限的 GitHub 账号，在 [lumen-journal](https://github.com/qcq14119/lumen-journal) 选择 **Code → Download ZIP**；在 AstrBot 插件管理中上传该 ZIP，启用后打开 **扩展功能 → 拾光手账**。私有仓库的普通网址安装不会继承浏览器登录，使用下载的 ZIP 安装。
2. 在“设置”填写 Images API 地址、Key、模型，点“暂存站点”，再点顶部“保存设置”生效。密钥图标打开管理弹窗，可添加、编辑、删除和手动选用；外部默认显示名称，眼睛按钮查看明文，点击编辑后直接显示已保存密钥，留空仍保持原值。
3. 在“角色参考”创建角色，填写外观和画风，上传图片并启用参考版本。
4. 在“相册”导入已有照片，或用“生成照片”创建画面。管理页任务只收入相册。
5. 需要聊天工具时，在角色配置中绑定完整的 AstrBot 会话标识。留空不会自动选择 QQ 会话；收到普通聊天后，可在页面选择最近会话。

更换参考只影响新任务；正在生成的任务和历史照片保留原参考版本。相册可单选/多选收藏、取消收藏、移到回收站或恢复。卡片悬停或键盘聚焦显示爱心与删除图标，触屏直接显示；详情底部爱心收藏，可编辑描述、下载，并查看原提示词、站点/模型和实际参考图，已清理参考明确占位。普通成图/导入照片自动供所属角色聊天与空间复用，无需逐张赋权。

## 聊天工具

| 工具 | 用途 |
| --- | --- |
| `album_search` | 查询当前会话照片或 purpose=reference 的临时场景，支持日期范围、收藏筛选和分页，只返回短描述和编号。 |
| `album_favorite` | 收藏或取消收藏1至9张当前会话照片，不发送或删除。 |
| `album_save_scene` | 为已收录的聊天图片添加简短场景描述，保留 24 小时参考用途。 |
| `album_generate` | 自动附带角色参考，可选择场景图；立即返回任务编号，后台完成后发到原会话。 |
| `album_send` | 复用已有照片，不调用生图。 |
| `album_publish_qzone` | 发布纯文字、1至9张已有成图，或用 job_id 登记生成后的自动续接发布；visibility 每条选择 private/friends/public。需要独立开启空间功能，配图仍核对角色/会话和回收站状态。 |
| `album_plan_schedule` | 角色在聊天中自主定下一条一次性「心念约定」（如稍后查岗、睡醒找对方、做好饭分享等），支持浮动时间窗、可选拍照以及单日早起/懒觉覆写（`override_day_wake=True`，次日自动恢复），触发后自动销毁。 |
| `album_plan_cancel` | 角色取消当前会话中尚未触发的一次性「心念约定」。 |
| `album_schedule_trip` | 角色在聊天中登记或取消多日特殊行程/出游模式（如节假日旅游需连续几天改为 08:00 早起，行程结束后自动恢复常驻作息）。 |

不设每日次数或固定拍照间隔。角色自然决定何时留下照片；不同消息的生图任务独立，最多同时处理3个，其余排队。同消息不重复提交，旧结果未知或下载失败不会挡住新请求。已有表情包和 QQ 工具保持原样。

任务接单后，只由主聊天回复一次已去准备并结合当前话题作自然反应，不再额外发送开始提示，也不要求用户先聊别的。完成后另生成简短接话，先发送文字、再单独发送照片，各有独立回执和去重键，失败也以角色口吻接话。通知不设置额外20秒截止；模型调用报错时使用中性提示，不向聊天转发技术错误。

模型调用的多图参数 `scene_asset_ids`、`asset_ids` 使用逗号分隔 ID 字符串，如 `img_a,img_b`，兼容部分 Gemini 中转服务的数组转换限制。内部 Python 调用仍支持列表，管理 API 与 UI 数据格式不变。

新安装默认关闭空间。需要新图配空间时，先调用 album_generate，再将返回的 job_id、文案与当次 visibility 交给 album_publish_qzone；后台等待该图完成后发布一次。已有成图仍用 asset_ids，二者互斥。文案和受众保存后不因默认设置变化而改变；发布前重新检查绑定、会话、空间开关和图片许可。缺少有效 tid 或调用结果未知时不重发；关闭功能、会话变化或图片不可用时保留意图。

同时使用其他空间插件时，需分别检查其发布开关；本插件的空间设置不会自动关闭其他插件的发布入口。

明确只发纯文字时，asset_ids 和 job_id 均留空；不需要角色参考或生成图空间默认许可，但仍检查角色绑定和空间总开关。填写的照片编号无效、无权限或生成失败时，不自动改发纯文字。三种发布方式共用逐条受众和投递去重。

用户来图是临时场景参考，保留 24 小时，不进入普通相册或作为空间素材。角色自主决定是否生成、是否在 scene_asset_ids 中选择当前/近期场景编号；空串表示只用角色参考。生成后的照片才进入普通相册，可在聊天与空间复用。

生成图默认保留 **30 天、最多 100 张**，在设置中可调整。启动、提交新生成前和每分钟检查保留规则，清理较旧且可删除的图片文件；收藏、角色参考、正在生成/发送或待核对任务涉及的图片受保护，可能暂时超过数量上限。若没有可删除图片，暂停新生图；磁盘可用空间不足 512 MB 时也不提交新生成或导入。按规则清理后只保留元数据，不能从回收站恢复文件。已被其他资产共用的哈希文件保留。该规则只管理插件副本，不删除用户源文件或 AstrBot 旧聊天历史。

## 服务与恢复

使用 Images API，有参考时调用 `images/edits`。不降级丢弃参考图。默认每站失败追加重试3次（总共4次），耗尽切备用站；可配置次数与等待时间。客户端另支持 `images/generations`，但首版角色工具要求已启用参考，无角色绘图尚无 UI 入口。

异步查询使用同站根路径 `/api/image-tasks?ids=...`。上游直返图片下载失败后，私密 results/ 保存原结果，可“恢复下载原图”，只重新下载、不重新生图；重启保留为待恢复状态。任务详情展开阶段、错误类别、HTTP 状态与投递回执。没有链接/编号的旧失败记录无法自动恢复；可在图片站下载原图后导入。已有任务编号才能继续查询；连接中断且没有编号时需要核对站点记录，不能直接重投。取消本地等待后，上游可能继续处理。

服务需兼容 multipart `image[]` 与 Images API 返回格式；参考图数量、异步返回和尺寸支持取决于所选服务，切换后应先验证。

只下载公开 HTTPS 图片。TUN 合成 DNS 地址仅对管理员明确配置的服务域名兼容，不开放任意下载域名/内网地址。切换服务不会将新密钥发给旧任务的服务。

## 数据

运行目录为 AstrBot 的 `data/plugin_data/astrbot_plugin_companion_album/`：

API Key 等真实设置通过管理页填写，只保存在运行目录。GitHub 与安装 ZIP 仅包含程序，不包含你的账号、设置、照片和任务记录；不需要手工修改源码或创建 `.env`。

```text
album.sqlite3     角色、版本、资产、任务和投递元数据
settings.json     私密服务设置，不应提交或分享
originals/        去除元数据后的无损 PNG，按内容哈希命名
delivery/         最长边 1600 的 JPEG 发送副本
thumbnails/       最长边 480 的缩略图
tmp/             原子写入的临时文件
results/         私密成图恢复来源（可能含临时签名URL/图片编码，不可公开分享）
```

停用本插件后整体备份此目录；在线备份需使用 SQLite backup API 并备份图片。回收站在自动保留规则执行前可恢复；自动清理会释放不再共享的图片文件。旧聊天迁移尚未实现。

新生图不会以 Base64 写入工具结果。AstrBot 既有图片历史不在本版自动清理范围内；接单在主聊天中只确认一次；完成、失败接话使用当前人格和任务摘要构成的独立上下文，临时读取最近少量纯文字聊天用于自然衔接，不回放媒体或工具历史、不复制到任务数据库。

升级前确认没有进行中的任务，再安装新 ZIP 并重载本插件；保留原运行数据目录。不要用跨出 AstrBot 插件目录的目录联接，宿主会拒绝发现其管理页。

## 朝夕拾记

时令日历可选择公共默认或具体会话，聊天设置的寒暑假、考试周和纪念日仅影响当前会话；公共配置作为尚未单独配置会话的默认值。完整日期 `YYYY-MM-DD` 只作用于指定年份，`MM-DD` 每年循环；明确留空不会重新填默认。行程必须是真实日期，聊天不能修改或取消其他会话的行程。

全年同步只使用政府来源检索结果并校验全年节日、年份及日期冲突；搜索/模型失败、数据不完整或保存期间版本已改变时，保留原日历并提示重试，不用推算结果覆盖。搜索连接“保存连接”只保存当前项，底部“启用此连接”只启用已保存连接；切换舍弃未保存草稿，已有 Key 可按需查看，修改地址须重新填写 Key。

一次性约定会收窄可能落到过去的提前窗口，并避让当前会话其他已启用计划的实际触发时间至少 20 分钟；单日早起覆写不与被其压制的晨间计划冲突。已销毁一次性计划的已结束足迹遵循历史保留策略，未知执行仍保留核对。远期预览不因无关行程而截断，修改接收会话会重新计算。

本插件独立保存与执行周期「日常作息」和一次性「心念约定」，不写入 AstrBot 的未来任务库。五段数字 cron 使用标准星期：1=周一、0/7=周日；日期与星期都受限时任一匹配，预览与执行使用相同规则。支持围绕基准时间配置浮动区间（`window_before` / `window_after` 分钟，基于确定性哈希抽样），模型会自动感知本次触发是提前、准点还是延后并给出自然反应。时区显式为 IANA 名称（如 Asia/Shanghai）。JSON 可导入/导出；旧 AstrBot 页面导出也支持，缺少时区时采用 Asia/Shanghai 并显示。导入先验证整份文件，全部停用，同名同会话不会重复导入或覆盖运行中的设置。

计划支持编辑、启停，定时规则可选每天、每周多日、每月日期与时间，也可手动输入时间表达式与浮动区间。修改时即预览未来5次含随机偏移的本地时间，未改规则保留原cron。每月不存在的日期不执行；不自动跳过节假日或跟随调休。到点使用当前会话人格、同日生活轨迹及近期纯文字上下文生成生活接话；支持按计划内容自动决定或每次附带拍照（先发文字消息，再后台异步生图并由 `notify_job` 补发照片或失败撒娇），也支持在周期计划触发时自主定下一条一次性后续「心念约定」（如没课查岗、早八后喊困、外出报备等，执行完即自动销毁，最多延续一层）。

朝夕拾记顶部固定导航可切换朝夕列表、时令日历、朝夕足迹和回收站。“时令日历”内置三合一可编辑日历（区间式国家法定节假日与调休补班表 `YYYY-MM-DD~YYYY-MM-DD=节日名`、`农历03-03` 广西壮族三月三/`农历07-07` 七夕等纯中文传统与地区节日及自定义纪念日、大学寒暑假与期末周区间），自动清理往年旧节假日与已结束行程防累增；支持聊天中由角色通过 `album_schedule_trip` 直接全托管登记/修改/取消多日特殊行程及更新寒暑假与纪念日，也支持在面板点击「同步全年节假日」（使用已启用的搜索连接检索官方放假调休通知，并结合聊天模型提取）。每条周期计划可绑定作息套组模式（`school_day` 上课日套组、`holiday_rest` 休息/假期套组、`sleep_before_work` 次日早起前夜催睡、`night_owl_before_rest` 次日双休/长假前夜熬夜），实现平时/假期两套作息自动顶替、周末四态精细区分（普通双休周末、法定长假连休周末、寒暑假周末、调休补班/单休周末）以及单日早起/多日出游覆写后到期自动恢复。“管理计划”支持单选、多选、全选，批量启用、关闭、删除；整批校验后保存。删除先停用并移到回收站，恢复仍停用，执行历史保留。每条外层开关可快速启停，直接显示上次执行时间/状态/偏移和下次预计时间；停用的下次时间仅为预览，不显示时区偏移后缀。启用不补发过去的时间，正在准备台词时停用/删除会在发送前重核，已经发出的消息不能撤回。

接收对象可选择相册角色、QQ机器人和私聊/群聊，直接填写QQ号或群号，也可选择已绑定会话；保存时原子新增绑定，失败或取消不留副作用。修改目标保留旧绑定。固定节日由角色结合日期自然表达；特殊日期例外已移除，旧例外也不再参与调度。本版不自动联网搜索调休。计划卡片用铅笔打开编辑；计划全选和相册全选本页均可再次点击取消。

任务按计划ID和触发时间持久去重；重启不补发停机期间的内容，发送未知不重发。同会话的上一计划仍在等待模型时跳过本次，最多4个后台计划并发。发送前检查计划未修改/停用、会话与角色未变化。执行记录只含状态和回执，不保存接话正文。导出的 JSON 含你配置的生活情境与目标会话，请按私人备份保存。

## 多站点与重试

设置页用名称下拉选择并编辑站点，最多5个；可改名、启停、设置顺序和首选。填写地址（通常包含/v1）与本站密钥后即可“获取模型”，无需先保存；从下拉选择或手动填写图片模型。“暂存站点”只暂存当前站点，切走会舍弃本站未暂存修改，其他暂存站点保留；顶部独立“保存设置”才统一生效，失败不清空编辑。刷新或离开设置页前需总保存。查看站点不改变首选生成站点，导航与总保存随滚动保持可见，三个面板同宽竖排。默认顺序重试耗尽再切站；“失败重试时同时请求备用站”默认关闭，开启会增加额度消耗。只采用最先取得可读图片的结果，备用获胜后优先使用该站；并行取消本地等待不代表上游取消。

524等网关错误可能已提交成功，默认记为未知；可单独开启“允许结果未知重试”，接受重复消耗额度的可能。已有上游任务编号继续查询；进程重启和恢复按钮不重新POST，历史任务不追溯重试。已生成的图片下载失败只重取原结果。任务详情可展开每次站点尝试和诊断。密钥默认显示名称，眼睛可临时查看当前密钥；改地址后需重新填写该站密钥。

每站最多20把独立命名密钥，在管理弹窗手动选用，其余保存备用，不自动轮换。列表每项可点眼睛核对完整密钥；点击编辑后直接显示内容，无需再点眼睛，外部仍默认隐藏。仅查看不算修改。弹窗取消/关闭/Esc舍弃本次修改；“完成”带回本站编辑，再暂存站点→保存设置。新任务使用提交时所选密钥，之后改选不改变旧任务查询；修改/移除原密钥会让旧任务保留待核对。密钥不进入普通状态、日志或聊天，关闭弹窗清除回显。

“暂存站点”在站点底部，与顺序和移除同栏；站点变更仍需顶部“保存设置”统一生效。所有页面的导航、标题和主要操作从打开起就固定在上方，滚动时位置不变；相册的收藏/来源分类、朝夕拾记的星期规则、设置标题与总保存也一起固定。

相册原图体积可在存储详情中查看。角色可结合话题翻看过去一周、一个月或出游照片，收藏有意义的照片、选取至多9张发空间；不新增强制周期发布。日期按Asia/Shanghai解释，文件日期不等于剧情发生日期。任务“未安排生成后发布”表示没有为该生成任务登记album_publish_qzone(job_id=...)，不是生图失败；后来用旧照发空间记在独立投递记录。

选图目录每页最多12条、每条描述最多240字符，仅含编号/日期/描述/收藏与来源，不给聊天模型发送图片或Base64。先按日期、关键词与收藏筛选，选定后才上传相应图片到QQ。当前描述来自生成画面要求或人工填写；一次性实际成图识别摘要和少量候选按需看图仍是后续计划。


收图在聊天模型回复前自动完成，普通来图无需再调用存图工具或单独确认；需要补充描述才使用album_save_scene。当前非流式来图轮次只发送最终自然回复，中间工具前台词不单独发，图片/表情与其他工具直接发送保持。真实工具调用仍可能需要一次结果续答，但保存图片本身不会单独调用模型。

只有accepted=true并取得job_id才表示照片任务已接单，queued可能仍在排队。校验失败明确返回原因，最终回复校正明确矛盾的“已在准备”句子。每个新请求独立，旧unknown不会锁住会话；同一消息的重复调用仍返回原任务，原任务的未知重试开关继续生效。未知旧任务可在任务记录核对后停止本地等待并保留记录；这不能取消上游可能仍在处理的任务。

最多3个任务并行生成，每项独立保存参考、重试和回执；超出排队，取消一项不影响其他。不同任务完成时，后台按顺序发送各自的文字和图片，避免完成通知彼此交错。任务并行不等于开启备用站竞速；后者仍默认关闭，开启后每个任务最多同时请求2个站点。

任务记录页分为生图任务、照片投递、计划执行，支持状态/角色/关键词筛选，每页20条。管理记录可单选、多选、全选本页再取消；清理前确认，状态变化或受保护项会阻止整批清理。自动检查只提示有更新，点击刷新再载入，避免打断选择。任务详情可直接恢复下载原图或停止本地等待，并查询该任务完整投递回执。

“保留设置”默认每类90天、最多1000条，独立保存；每分钟分批清理较旧已结束详情，每类每次最多200条。活动任务、待恢复原图、未知结果/投递和计划最后执行受保护，可能超过上限。清理不删除照片，其生成提示词/参考/站点型号继续可查看；留下精简防重摘要，避免旧事件重做。详细日志清理后不可恢复，数据库释放空间供后续复用，摘要与照片元数据仍会缓慢增长。
